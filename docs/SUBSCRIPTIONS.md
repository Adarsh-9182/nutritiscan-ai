# Accounts and subscriptions

The canonical identity remains the FastAPI health account. Browser sign-in sets a root HttpOnly opaque session and a separately signed account proof, bound to the session hash. Public account/billing checks verify revocation through `/consent`; they do not read health records. Existing scoped sessions still work in the health space; signing in again bridges them to public chats. Native bearer authentication is unchanged. Google sign-in additionally requires matching Google OAuth client IDs on the site and health service; these cannot be generated from an email/password account.

Billing uses the existing site Neon connection. `node scripts/migrate-billing.mjs` adds only `ns_billing_*` tables. No password, medical content or chat text is copied. Local PGlite installs the same schema. The migration is safe to rerun. Never print or commit production connection strings.

## Activation

Live checkout is disabled by default. Confirm the market, actual recurring prices, currency, merchant account, refund/support terms and paid-model budget before enabling it. No merchant products or live purchases are created by this implementation.

1. Configure `AI_GATEWAY_API_KEY` with a funded Gateway account. Recheck the pinned models and standard short-context prices in `lib/billing/models.ts`, run medical/research evaluations, then set `PREMIUM_AI_ENABLED=true`. Paid access still requires an active verified DB subscription. Free and anonymous calls cannot reach Gateway models or paid embeddings.
2. Set `BILLING_PROVIDER=stripe` or `razorpay`, `BILLING_CURRENCY=INR` or `USD`, `PRO_MONTHLY_PRICE_MINOR`, `MAX_MONTHLY_PRICE_MINOR`, and explicit usage budgets `PRO_MONTHLY_AI_CREDITS` / `MAX_MONTHLY_AI_CREDITS`. One credit is $0.01 of configured model cost, not a token count or stored monetary balance. Defaults are 500 / 2000 credits. Choose sale prices that cover model use, platform/payment costs and taxes.
3. Stripe: configure `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRO_PRICE_ID`, `STRIPE_MAX_PRICE_ID`. Prices must be active, monthly, interval_count=1, licensed, and exactly match the displayed amount/currency. Configure the customer portal for payment methods/cancellation; keep plan switching disabled until evaluated. Tax-inclusive/exclusive merchant prices must match the terms shown at hosted checkout.
4. Razorpay: configure `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`, `RAZORPAY_PRO_PLAN_ID`, `RAZORPAY_MAX_PLAN_ID`, and explicit `RAZORPAY_TOTAL_COUNT` (1–120 monthly cycles). Plans must exactly match displayed price/currency. The hosted mandate shows its finite duration. Cancellation of renewal is available in `/account`.
5. Register `/api/billing/webhook` on the selected merchant account. Stripe: subscribe to checkout session, customer subscription, invoice, charge refund and dispute events. Razorpay: subscription lifecycle/charged, refund processed and payment dispute events. Preserve raw body signatures. This endpoint uses event IDs, server-minted checkout bindings and authoritative API reads; redirect URLs do not activate a plan. Refund/dispute events put the account on a persistent hold pending owner review; later active events do not clear it.
6. Use a separate Vercel preview deployment with test keys and test webhook secrets. Validate successful/failed renewal, duplicate and reordered delivery, cancellation, refund, dispute and outages. Preview/local test entitlements never unlock paid Gateway calls. Production requires live keys and ignores sandbox entitlements. Set `BILLING_ENABLED=true` only after successful merchant end-to-end testing and approved sale prices. Verify a real owner-controlled paid account without making purchases on another person's behalf.

Use an explicit random `ACCOUNT_SESSION_SECRET` of at least 32 characters to manage shared-session signing independently. Until supplied, a domain-separated HMAC key is derived from the existing 64-hex `HEALTH_DATA_KEY`; never rotate that encryption key to change a session secret.

## Access, limits and operations

Pro selects `openai/gpt-6.1-sol`; Max selects `openai/gpt-6-astra`. Health safety/triage and Research quote/support checks remain in place. Research planning and support review use Gemini. A premium failure can fall back to basic access, with a notice; Research records the model actually used. Stronger model access is not clinical validation.

Paid calls are text-only and function-tool-only, capped at 80KB of serialized context, 3000 output tokens and six provider calls per turn. An atomic reservation is made before every paid provider call. Reported usage settles it once; uncertain timeouts/disconnections retain the reservation. The stream is never treated as proof of zero provider work. Credits reset with the verified subscription period and do not roll over. Review retained reservations against provider billing before any manual adjustment. Reconcile provider events and costs during rollout; there is no automatic refund policy implemented here.

Pending hosted checkouts are unique per account. Stripe retries reuse an idempotency key; uncertain Razorpay attempts are held until expiration, avoiding duplicate mandates. Recurring accounts cannot create a second subscription. Account deletion is blocked while a recurring subscription remains; cancel renewal and wait for termination first. Deleting health data must never leave an unmanageable active charge.

`npm run verify` covers SQL entitlement/usage tests, session/proxy boundaries, payment signatures/prices, premium routing/metering and UI flows, plus the existing safety gates. Merchant end-to-end and live paid-model testing require configured accounts and remain separate release gates.
